# Корпоративная версия (установка у клиента)

Статус: **запланировано, не начато.**

## Вводные (со слов заказчика)

- Одна конкретная компания-клиент.
- У них всё своё: комиссия, обучения, тесты, сотрудники. База данных — с нуля.
  Нашу базу **не переносим** (в ней персональные данные других организаций).
- Система ставится **на сервер клиента, в закрытую сеть**. Интернета и доступа
  к нашему git там, скорее всего, нет.
- Доработки мелкие, делаются по ходу.

## Принцип

Один код на обе версии, отличия через `.env` и флаги функций.
Отдельный репозиторий не делать: иначе каждый фикс придётся делать дважды.

## План работ

### 1. Подготовка кода (у нас)
- Исправить всё из таблицы через `.env`, чтобы наша версия работала как сейчас.
- Скрипт первичной инициализации: миграции, первый суперадмин
  (`backend/scripts/seed_admin.py` уже есть), справочники (типы обучения
  БиОТ/ПТМ/ПромБез, сроки действия).

### 2. Офлайн-пакет
```
ozen-lms-corp-vX.Y/
├── images.tar            # docker save: backend, frontend, postgres:15-alpine, nginx:alpine
├── docker-compose.yml    # image: вместо build:
├── .env.example          # без наших секретов
├── nginx.conf
├── install.sh            # docker load, генерация паролей и SECRET_KEY, миграции, первый админ
├── update.sh             # docker load новой версии + alembic upgrade head
├── backup.sh             # pg_dump + папка storage
└── README.md             # инструкция для их IT
```
Передача на флешке или по разрешённому каналу, с контрольной суммой (sha256).

### 3. Установка у клиента
1. `docker load` → `./install.sh`.
2. Вход под первым админом, дальше клиент заводит всё сам.
3. Резервное копирование по расписанию (cron `backup.sh`). Это их зона ответственности.

### 4. Обновления
Каждая версия — пакет с номером и git-тег у нас. У клиента: `./update.sh`.

## Вопросы к IT клиента
1. ОС сервера, установлен ли Docker? Если нет, нужны офлайн-пакеты.
2. Ресурсы: минимум 2 CPU / 4 ГБ RAM / 50 ГБ диска.
3. Внутренний адрес (домен или IP) и сертификат для HTTPS.
4. Доступ к pki.gov.kz из их сети.
5. Удалённый доступ для нас (VPN/AnyDesk) или только выезд.
6. Способ передачи файлов в закрытую сеть.
